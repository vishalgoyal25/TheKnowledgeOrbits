# Code Quality

# ruff — PINNED EXACTLY, and it MUST stay in lockstep with two other places:
#   .github/workflows/ci.yml   -> pip install ruff==0.4.4  (blocking gate)
#   .pre-commit-config.yaml    -> ruff-pre-commit v0.4.4
# Previously ruff was absent from this file entirely, so a developer's machine
# ran whatever `pip install ruff` had fetched, while CI ran 0.4.4. Formatting
# differs between ruff minors, so that gap could turn a green local run red in
# CI on identical code — the same failure mode the mypy pins below describe.
# The write-time formatter hook (.claude/hooks/format-on-write.ps1) uses this
# venv's ruff, which is exactly why it has to be pinned here.
ruff==0.4.4
#
# REMOVED 2026-09-02: black, flake8, isort.
# ruff replaced all three. Leaving them installed was actively dangerous, not
# merely redundant: black and `ruff format` disagree on edge cases, so running
# black (e.g. via the stale `just format-backend` recipe) would reformat the
# tree into a state `ruff format --check .` rejects in CI. A dead tool that can
# still be invoked is a landmine. NOTE: Justfile's format-backend/lint-backend
# recipes still reference them and need updating.
#
# Type checking — PINNED EXACTLY, deliberately.
#
# These were `>=`, so CI installed whatever had shipped that morning while a
# developer's machine kept whatever it installed months ago. On 2026-08-16 that
# drift turned a green local run into a red CI run on identical code: a newer
# stub set began reporting `request.data` as `dict | list`, so four pre-existing
# `.get()` calls in engines/auth, knowledge and userstate became union-attr
# errors. Nothing had changed in those files for months.
#
# A type checker is part of the build's definition of correct, so it must be
# reproducible — same reason ruff is pinned to an exact version in ci.yml.
#
# Upgrading these is a deliberate task: bump them, run `mypy .`, and narrow the
# request.data types the new stubs complain about. Not something to inherit
# silently from a release that happened overnight.
mypy==1.20.0
django-stubs==6.0.2
djangorestframework-stubs==3.16.9
types-requests>=2.32.0.20241016
